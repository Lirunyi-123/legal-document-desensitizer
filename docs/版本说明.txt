# 法律文书脱敏工具 v3.2 版本说明

## 版本号
v3.2 — 手机号式微信号（微信号=手机号的常见场景）

## 背景
很多人的微信号就是手机号（"微信号：13800138000"）。原规则层：
- 纯 11 位手机号：手机号规则先执行，已正确脱敏为 [手机号] ✓（本就可用）
- 但两种形态漏/错：带分隔符 `138-0013-8000` 完全漏脱敏；带 +86/86 前缀的
  `+8613800138000` 被后执行的金额规则误标成 [金额]（13 位纯数字）

## 修复
- 微信号上下文规则号体增加"手机号形态"：`(?:\+?86)?1[3-9]\d(?:[-\s]?\d{4}){2}`
  （可选 +86/86 前缀、3-4-4 分隔，容忍 -/空格）
- 执行顺序保证：微信号规则在金额规则之前 → 86 前缀形态被抢先替换为 [微信号]，
  不再误标 [金额]
- 纯 11 位仍由手机号规则输出 [手机号]（语义更准），行为不变

## 回归
- 单测 104 → 110（新增 TestV32WechatMobile 6 个）
- 红队语料 84 → 89（新增 wx_10~13 + neg_12），105/105 命中、误报 0
- 合成语料 300 条 99.76% 召回、误报 0；训练语料还原往返逐字节一致

# 法律文书脱敏工具 v3.1 版本说明

## 版本号

## 1. 微信号脱敏增强（修复"微信号无法正常脱敏"）
- 上下文词表扩充："微信号码"，并容忍 OCR 行内空格（"微 信号"）
- 分隔符支持 "：: 为 是 ="——"微信号是xxx"、"微信号为xxx"、"微信号码xxx"、
  "我的微信是xxx" 等法律文书/聊天记录常见写法全部脱敏
- 号体仍为 5~20 位字母开头；后接中文时天然不匹配，不误伤
  "微信是常用的聊天工具" 这类普通句子
- mask 与 scan 共用同一正则（_WECHAT_PATTERN），扫描与脱敏行为一致

## 2. 姓名+高频动词尾 误报防护（修复"双方确认/张三确认"被当人名）
- v3.0 为修"荣墨军称"（jieba 切"荣墨"+"军称"）放开了"名 token 带尾动词"，
  副作用是把"张三确认"拆成"张三确"+"认"（"认"是合法尾词）造成误报
- 新增 _NAME_FOLLOW_BLOCK：确认/约定/同意/协商/支付/收到 等高频完整动词，
  在"名 token 带尾动词"放宽与角色词尾部回退两处都整体排除
- 角色词路径优先按"完整动词尾"回退（"张三确认"→"张三"+"确认"），
  而不是先按单字切
- 黑名单补"时候 时侯 时辰 时间 时点 时刻"（"什么时候"不再被当人名）

## 回归
- 单测 94 → 104（新增 TestV31Wechat 5 个 + TestV31NameVerbTail 5 个）
- 红队语料 77 → 84（新增 wx_05~09 + neg_10/11），100/100 命中、误报 0
- 合成语料 300 条 99.76% 召回、误报 0；三份训练语料还原往返逐字节一致

# 法律文书脱敏工具 v3.0 版本说明

## 版本号
v3.0 — 内化 rizzo-pii 五大优点：合成语料管线 + validated 校验标记 + PDF 真·涂黑 + 还原漂移容忍 + P/R/F1 评测口径

## 背景
参照开源项目 Rizzo-AI-Academy/rizzo-pii（意大利语 PII 脱敏：LLM 写模板、代码注入
校验值、PDF 真涂黑、per-tag 评测），把五个最值得借鉴的设计内化到本工具。

## 1. 合成语料管线（synthetic/）— LLM 写模板、代码注入校验值
- llm_template_bank.py：LLM（OpenAI 兼容）写中文法律文书模板，只允许白名单占位符
  {当事人甲} {身份证} {银行账号}…，QA 门控 find_stray_names 丢弃占位符外夹带姓名的模板。
- generate_synthetic_pii.py：代码生成数学上合法的号码（身份证 GB 11643-1999、
  信用代码 GB 32100-2015、银行卡 Luhn，全部通过 desensitize 校验器），自动填
  expect_masked/expect_kept 输出红队语料；--bio 输出 BIO 训练语料。
- 内置 11 个中文模板兜底（不接 LLM 也能用）；实测 120 条规则层召回率 99.6%、误报 0。
- 合成语料驱动修复 4 个规则层真实盲区：
  a) 角色词缺"被告人/被申请人/当事人/经营者"（刑事/行政处罚文书高频）→ 已补；
  b) "25日在安徽省…"地址规则吞"日"（省/市/小区前缀吞日期尾字）→ 前缀排除"日月年号"；
  c) jieba 把"荣墨军称"切"荣墨"+"军称" → 姓名形态校验容忍"名 token 带尾动词"；
  d) 4 字名（复姓+2字名）超出姓名形态判定 → 生成器按真实分布规避。

## 2. 校验码 strict/lenient 双档 + validated 标记
- 统一检测器表语义：strict=True（形状泛、校验不过即丢弃：无标签身份证）；
  strict=False（形状特异/标签权威、校验不过也脱敏：带标签身份证/银行卡/信用代码）。
- 映射表 Markdown 新增"验证"列：✓=校验码算法通过，—=仅格式/标签命中；
  Mapping 增加 validated 字段（JSON 输出/解析兼容，旧映射表无此列不报错）。
- scan 输出带 validated/strict。

## 3. PDF 真·涂黑脱敏（pdf_redact.py）
- mask -f x.pdf --pdf-redact -o x_redacted.pdf（或 -o 指定 .pdf 自动启用）。
- 字符级精确匹配（rawdict 每字符 bbox）+ 容忍 OCR 空格/换行 + 数字/字母词边界；
  值长优先 + 已涂矩形跳过（张三不破坏张三丰）。
- 清理元数据/XMP、批注、表单字段、书签、内嵌附件。
- 安全语义：residual 零残留校验（原文仍可读→拒绝交付）；全文零命中（扫描件）→
  报错不交付"假脱敏"；过短值跳过并警告。

## 4. 还原容忍 markdown 漂移（restore_text）
- 按键长倒序 + 正则 \**\[?\s*占位符\s*\]?\**：加粗/丢括号/多余空格均可无损还原。
- 先精确后宽松两遍防"语义 inner 词撞上下文前缀"（总金额[金额] 不误吞）；
  精确/漂移混用按原文顺序配对；首尾空格保留。

## 5. 评测口径：entity-level per-tag P/R/F1 + support（evaluate.py）
- 正样本 expect_masked（TP/FN）、负样本 expect_kept（FP→precision 分母）。
- 分类型 precision/recall/F1 + support + MICRO/MACRO；控制台/Markdown/JSON 全输出。

## 回归
- 单测 74 → 93（v3.0 新增 19：validated/还原漂移/规则盲区/合成语料/PDF 涂黑）。
- 红队语料 77 条：100% 召回、误报 0；合成语料 120 条：99.6% 召回、误报 0。
- 三份训练语料还原往返逐字节 0 差异。

# v2.8.1 推送方式

## 本机推送到 GitHub 的标准方式（网络受限环境）
- `git push` 直连 github.com:443 常被阻断；改用 `git-push-api.py` 通过 GitHub REST API 推送（curl 传输，api.github.com 可达）。
- 用法：本地正常 `git commit` 后执行 `python3 git-push-api.py --sync-local`。
- 特性：逐个重建本地领先提交；blob SHA 逐字节核对；`--sync-local` 用"消息换行 × 时区偏移"组合把远程提交对象还原到本地，本地 main 与远程 SHA 完全一致。
