# 法律文书脱敏工具 v3.6 版本说明

## 版本号
v3.6 — 列感知脱敏（银行流水表格直接上传处理）+ 审计清单孤立姓名 WARN

## 背景
用户提出 9 项硬性要求（不依赖 OCR/理解表格结构/识别字段含义/支付宝-姓名/
账号+姓名/无前缀姓名/企业名称/自动检查遗漏/审计报告）。逐条实测后 5 项已达标、
4 项未达标（不依赖 OCR 部分、字段含义、孤立姓名、审计查不出孤立姓名）。
本次针对 Excel 与带文本层 PDF 的表格路径，用"列感知"统一解决字段含义+
孤立姓名+审计三问题；扫描件 PDF 仍需 OCR（工具明确报错引导）。

## 1. 结构化读取（read_structured_table）
- .xlsx：openpyxl 读行，首行作表头候选
- .pdf：PyMuPDF `find_tables(strategy='text')`（电子银行导出流水 PDF 常见；
  实测带线/无线表格均可提取，中文用 china-s 字体验证通过）
- 校验：表头含 ≥2 个已知列类型关键词才返回结构化，否则 None → 回退普通文本
  （保证非表格文档行为不变，134 个既有单测全部保持通过）

## 2. 列类型识别（_COL_TYPE_RULES / _classify_column）
户名（对方账号与户名/对方户名/交易对手/收款人/付款人…）> 日期（交易日期/
记账日期）> 金额（交易金额/账户余额/收入/支出）> 附言（附言/摘要/备注）

## 3. 列感知脱敏（mask_table / _mask_cell）
- 每格独立 `_run_rules`，共享 EntityResolver → 同一对手全表统一占位符
  （"支付宝-刘方立" 与 "7399/支***刘方立" 的刘方立同号）
- 户名列：孤立中文姓名（2~4 字、姓氏开头、整格无其他内容）强制识别——
  解决"对方户名列只有胡若薇一个值、count=1 漏掉"的硬伤
- 日期列：不脱敏（业务信息非敏感）
- 附言列：`_run_rules_no_amount` 跳过金额 pass——12 位联行号 340690400059
  不再误标 [金额]
- **事件坐标修复**：初版每格事件位置相对各自单元格，_build_event_mapping
  全文回放错乱 → 增加 `_event_offset`（每格全文偏移），_record_event 自动
  加偏移 = 全文坐标，restore 逐单元格无损还原（含类型）

## 4. 审计清单增强（要求 8）
- `scan_remaining_risk` 新增"孤立姓名候选"：普通模式下漏掉的孤立姓名
  在审阅清单显式提示（姓氏+jieba+黑名单+财务/表头词排除，误报可控）
- 金额残留跳过 12~13 位非 19/20 开头数字（联行号不误报）
- 实测：列感知端到端审计报告"关键信息 0 残留 + 还原往返逐字节一致 + 无残留提示"

## 回归
- 单测 134 → **141**（TestV36TableAware 7 个：结构化读取/无表头回退/列分类/
  孤立姓名识别/日期与联行号保留/审阅残留检测/表头词无误报）
- 红队 105 项 MICRO/MACRO 全 1.0000、误替换 0（规则层无回归）
- 自检 6 项必检全部通过（LLM 项本机未启动 Ollama 时 SKIP/FAIL 属环境降级）
- 端到端：4 行真实银行流水 xlsx --table-aware → 脱敏文件 + 审阅清单 +
  映射表 + restore 还原逐单元格含类型一致

## 已知边界
- 扫描件 PDF（无文本层）仍需先 OCR（工具明确报错并给出指引）
- PDF 表格提取对"窄列/无表头"排版可能合并列（真实银行流水排版通常规整）
- 列感知仅对表头可识别的表格生效；无表头文档走原有普通文本路径

# 法律文书脱敏工具 v3.3 版本说明

## 版本号
v3.3 — Excel（.xlsx / .xlsm）支持：银行流水、证据清单、对账单单元格级脱敏

## 背景
律师处理证据材料时高频遇到 Excel 格式（银行流水、对账单、证据清单、往来明细），
原工具仅支持 .txt / .docx / .pdf。本次新增 .xlsx / .xlsm 完整支持：
mask / scan / restore / full / semantic 五个子命令全部自动获得 Excel 能力
（它们都走 read_text_from_file + write_desensitized_file 两个公共入口）。

## 方案（复用 docx 的"行序映射"架构）
- 读取：按 工作表顺序 → 行序 → 列序 把每个参与脱敏的单元格展平为一行文本；
  单元格内换行用 ␊（U+240A）标记占位，写回时还原，保证一行 ↔ 一单元格。
- 跳过规则（读取与写回共用 _xlsx_cell_text，行序严格一一对应）：
  - None（空单元格 / 合并区非左上角）
  - 公式（str 以 '=' 开头）——公式是结构不是内容，误替换会毁掉计算
  - 日期时间、布尔单元格——保持原样与格式，不参与脱敏
  - 数值（int/float）：整数值转干净整数文本（880000.0 → '880000'），
    便于金额规则匹配
- 写回：仅当脱敏引擎实际改动过该单元格才回写；未改动保持原值
  （数值/日期类型与格式原样保留）。keep_vba=True 支持 .xlsm 宏不丢。
  保存后 chmod 0o600（仅当前用户可读写）。
- 还原（restore）：restore 以**脱敏文件**为基底时（CLI 真实用法），
  按映射表恢复数值类型——_coerce_restored_numeric 把金额等数值类还原为
  int/float；身份证/银行卡/手机号/证件号等号码类（_TEXT_NUMERIC_AS_TEXT_TYPES
  黑名单）即使全数字也保持文本，避免账号被转成数值/科学计数法。

## 修复的过程问题
- CLI 端到端首次验证发现：restore 以脱敏文件为基底时金额 float 还原成 str
  （类型丢失）。修复：write_desensitized_file 新增 mappings 参数，
  restore 命令传入，按映射表类型恢复数值。函数级冒烟（基底=原文件）本就
  通过，但 CLI 真实用法（基底=脱敏文件）需此修复。

## 回归
- 单测 110 → 120（新增 TestExcelSupport 10 个：展平顺序/写回单元格级/公式保留/
  往返还原含类型/CLI 风格 restore 类型恢复/多表统一占位符/依赖缺失优雅退出/
  宏保留/空表不崩溃/微信号单元格）
- 红队语料 89 条：105 项命中（MICRO/MACRO 全 1.0000）、误报 0，规则层无回归
- CLI 端到端冒烟（银行流水.xlsx）：mask 正确脱敏 [身份证号]/[手机号]/[金额]/
  [公司_1]/[地址]/[邮箱]，公式 =SUM 保留、合并区保留、单元格内换行还原；
  restore 往返逐单元格一致（金额恢复 float 392485911.675、账号保持 str）

## 使用
```bash
pip3 install openpyxl
python3 desensitize.py mask -f 银行流水.xlsx --save-mapping 映射表.md
python3 desensitize.py restore -f 银行流水_desensitized.xlsx -m 映射表.md -o 还原.xlsx
```

## 已知边界（v1）
- 老式 .xls（Excel 97-2003）不支持，请另存为 .xlsx 再处理
- 批注/超链接文本不处理（openpyxl 写回会丢失批注作者/时间戳等元信息）
- 公式单元格不脱敏（二期可考虑字符串常量）

- 执行顺序保证：微信号规则在金额规则之前 → 86 前缀形态被抢先替换为 [微信号]，
  不再误标 [金额]
- 纯 11 位仍由手机号规则输出 [手机号]（语义更准），行为不变

  a) 角色词缺"被告人/被申请人/当事人/经营者"（刑事/行政处罚文书高频）→ 已补；
  b) "25日在安徽省…"地址规则吞"日"（省/市/小区前缀吞日期尾字）→ 前缀排除"日月年号"；

  d) 4 字名（复姓+2字名）超出姓名形态判定 → 生成器按真实分布规避。

## 2. 校验码 strict/lenient 双档 + validated 标记
- 统一检测器表语义：strict=True（形状泛、校验不过即丢弃：无标签身份证）；

- 映射表 Markdown 新增"验证"列：✓=校验码算法通过，—=仅格式/标签命中；
  Mapping 增加 validated 字段（JSON 输出/解析兼容，旧映射表无此列不报错）。
- scan 输出带 validated/strict。

## 3. PDF 真·涂黑脱敏（pdf_redact.py）
- mask -f x.pdf --pdf-redact -o x_redacted.pdf（或 -o 指定 .pdf 自动启用）。
- 字符级精确匹配（rawdict 每字符 bbox）+ 容忍 OCR 空格/换行 + 数字/字母词边界；
  值长优先 + 已涂矩形跳过（张三不破坏张三丰）。
- 清理元数据/XMP、批注、表单字段、书签、内嵌附件。
- 安全语义：residual 零残留校验（原文仍可读→拒绝交付）；全文零命中（扫描件）→
  报错不交付"假脱敏"；过短值跳过并警告。

## 4. 还原容忍 markdown 漂移（restore_text）
- 按键长倒序 + 正则 \**\[?\s*占位符\s*\]?\**：加粗/丢括号/多余空格均可无损还原。
- 先精确后宽松两遍防"语义 inner 词撞上下文前缀"（总金额[金额] 不误吞）；

- `git push` 直连 github.com:443 常被阻断；改用 `git-push-api.py` 通过 GitHub REST API 推送（curl 传输，api.github.com 可达）。
