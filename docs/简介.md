# 法律文书脱敏工具（Legal Document Desensitizer）

> **面向中国律师与法律实务的本地优先文书脱敏工具**
> 规则引擎 + 语义占位符 · 两阶段工作流（审阅清单） · 加密映射表 · 一键无损还原 · 红队评测量化

---

## 一句话介绍

把判决书、合同、聊天记录、证据材料里的敏感信息（身份证号、手机号、银行卡号、
人名、地址、金额、案情细节……）自动替换为语义占位符（`[当事人甲（原告）]`、
`[身份证号]`），同时生成加密映射表，需要原文时一键无损还原。

**核心承诺：结构化数据零依赖本地处理、可量化验证、可无损还原、不盲目信任模型输出。**

---

## 为什么需要它

律师日常工作离不开涉密文书：起诉状、判决书、合同、尽调报告、聊天记录。
对外分享、上传 AI 辅助、交给协作方时，一条没脱敏的身份证号或当事人姓名
就可能构成泄密。而通用工具不懂中国法律语境，要么漏掉案号、信用代码、
律师执业证号这类中国特有实体，要么把"粤B88888"车牌当微信号、把日期当身份信息。

本工具专为中国法律文书设计，覆盖 20+ 类中国法律敏感实体，并针对
**律师真正关心的三件事**做了设计：脱得干净、查得到底、还原得回来。

---

## 适用场景

- 判决书 / 裁定书 / 调解书的对外脱敏
- 合同、协议中的当事人信息与商业条款脱敏
- 微信聊天记录、邮件等沟通证据的提交前脱敏
- 尽调材料、证据册的涉密信息筛查
- 文书上传云端 AI 前的预处理（结构化号码本地先替换）
- 律所内部归档 / 协作时的隐私合规
- **格式预处理**：docx / pdf / html / csv / 扫描件图片先经内置 `format-converter`
  转成 txt / md / json 再脱敏（判决书 PDF、网上复制的裁判文书、当事人名单等）

## 好用的地方（核心亮点）

### 1. 中国法律实体全覆盖（规则层，无需模型）
身份证号（GB 11643 校验码）、统一社会信用代码（GB 32100 校验码）、银行卡号
（Luhn）、手机号、固定电话、邮箱、微信号、QQ 号、律师执业证号、组织机构代码、
护照/港澳通行证/驾驶证、案号（含全角括号）、车牌号、出生日期、金额、
角色人名、裸人名、公司名、地址（含无省市区层级的写法）。

### 2. 语义占位符，律师可读
不是打马赛克，而是替换为带角色语义的占位符：

```
原告：陈建国，男，住浙江省杭州市西湖区文一西路1号
→ 原告：[当事人甲（原告）]，男，[地址]
```

同一人物全文对应同一个占位符（实体归一化 + 种子传播），案情脉络完整保留。

### 3. 加密映射表 + 一键无损还原
- AES-256-GCM + PBKDF2 加密映射表，密钥不落终端
- `restore` 一条命令把脱敏文书还原为原文，**逐字节一致**
- 多个同类型占位符按原文顺序配对，多个 `[金额]` 也不会还原错位

### 4. 红队评测，用数据说话
内置 60 个红队用例（正样本 + 负样本，含真实判决书实战负样本），一键输出分类型
召回率/误报/泄露报告。
当前基线：**60/60 通过，结构化期望 70 项召回率 100%，保留项误报 0，泄露 0**。
每次改规则后跑一遍，量化"有没有变差"。

### 5. 失败安全，不盲目信任模型
LLM 层输出若增删行数、改动已有占位符、声称替换的值仍残留原文，
整套输出被拒绝并中止——宁可报错，也不产出"看起来脱敏了其实没有"的文档。

### 6. 可复现、可自检
`selfcheck.py` 一键验证：文件、59 项单元测试、红队评测、还原往返全部比对，
任何 AI/同事拿到的拷贝，跑一遍就知道是不是和官方一致。

### 7. 两阶段工作流，无需接入任何外部 API
- **阶段一（规则层）**：关键信息（身份证/手机号/银行卡/案号/信用代码/执业证号等）
  本地规则必清；`mask --review` 一次生成"脱敏文书 + 审阅清单"，清单自动校验
  关键信息是否清零，并列出剩余低优先级项供律师逐条确认
- **阶段二（语义层）**：律师审阅后说"继续语义层脱敏"，配置了本技能的 AI
  直接执行，**无需 Ollama、无需 API Key**；只处理低优先级信息
  （法院名称、案情敏感细节、裸公司简称、OCR 变体写法）
- 本地 Ollama / 云端 OpenAI 兼容 API（通义 / DeepSeek / 智谱）仍为可选替代，
  不再是默认依赖

### 8. 实战打磨，专治 OCR 扫描版文书
以一份 42 页 OCR 扫描判决书做端到端验证（规则层 + 一键还原）：- **387/387 段无损还原**，映射表逐字节一致（含 "349976351 元 " 这类数字与单位
  间带空格、尾随空格的写法）
- 角色词后名词不再误伤：`原告提供担保`、`法定代表人处签名`、`法定代表人印章`、
  `被告私章` 等词组保留原样
- 公司名不吞上下文：全称前被误吞的"原告…与被告"等上下文词会被修剪，
  只替换公司名本身（`原告[当事人甲（原告）]与被告[合同乙方]`）
- OCR 空格兼容：公司简称内部、金额数字与单位之间的空格均可正确识别
  （如 `32000万 元整`）
- 金额支持无单位大数（结算算式 `392485911.675`）
- **OCR 识别最低限度（实测数据，v3.7-3.9）**：
  - **字号下限 ≈ 8pt**（约 11px @96dpi）：≥8pt 稳定识别；6pt 低清下失败
  - **分辨率 ≥150 DPI**（工具默认 200 DPI 渲染）：72 DPI 仍可识别 10pt 字号
  - **长度无下限**：单个汉字、短账号均能识别
  - **真正的限制是质量而非大小**：低清渲染（<6pt/150dpi）失败，但同字号
    300dpi 成功；OCR 错字（`徐常英`→`徐第英`、`6212`→`I12`）是所有 OCR
    引擎的固有局限
  - 手机高清截图、网银导出 PDF、≥200 DPI 扫描件：直接可用；
    低清翻拍/传真件识别率下降，审阅清单会列出 not_found/残留供人工确认

### 9. 合成语料管线 + PDF 真涂黑 + 可量化评测（v3.0）
- **合成语料**：LLM 写中文法律文书模板（只允许占位符），代码注入数学上合法的
  号码（身份证 GB 11643 / 信用代码 GB 32100 / 银行卡 Luhn），自动标注期望值，
  一条命令扩出数百条红队语料（300 条召回 99.76%、precision 1.0、误报 0）
- **PDF 真·涂黑**：`--pdf-redact` 输出保留版式的涂黑 PDF，字符级精确匹配 +
  OCR 空格容忍，清元数据/批注/表单/书签/附件，residual 零残留校验（原文仍可读
  就拒绝交付；扫描件零命中直接报错，不交付"假脱敏"）
- **原图涂黑（v3.9）**：`--image-redact` 图片/截图输入直接在**原图上涂黑**
  敏感区域，保留原图版式输出 PDF（Vision 带坐标 OCR 定位 + 双层 residual
  校验：像素级确认涂黑 + OCR 复查）；实测 76 处涂黑覆盖页面 25.4%
- **可量化**：评测升级为 entity-level per-tag P/R/F1 + support，负样本计 FP，
  改规则跑双基线（红队 77 条 + 合成语料）即知"改保守了还是改漏了"

### 10. 内置格式转换 format-converter（v4.1）
- **纯 JS 无外部引擎**：docx（mammoth）/ pdf（pdfjs-dist）/ 文本互转（turndown、
  marked、csv-parse）/ 图片（sharp）全部本地处理，`npm install` 即可用
- **扩充脱敏输入链路**：判决书 PDF → txt、网上复制的裁判文书 HTML → md、律师
  文书 docx → txt、当事人名单 csv → json、扫描件图片 → pdf，先转格式再脱敏
- **扫描件识别**：无文本层的图片型 PDF 明确报错并指引走 OCR 通道，不静默
  产出空文件（16 项端到端自测兜底）
- 刻意排除与脱敏无关的转换（音视频 / NCM / ZIP / Office 全格式），保持轻量

> ⚠️ **使用决策（重要）**：format-converter 是**单向提取器**，转换后丢失版式且
> **不支持转回 docx/pdf**（`restore` 只还原内容、不还原格式）。需要最终
> docx/pdf 原格式（归档/庭审/提交）时**不要先转换**，直接 `mask -f 合同.docx`
> 或 `mask -f 判决书.pdf --pdf-redact`（保格式、可还原）；只有需要提取文本
> （核对/摘录/喂 LLM）或输入是 html/csv/heic 等脱敏工具不直接支持的格式时，
> 才先用 format-converter 转成 txt/md/json。**要"转回原格式"就别转，直接脱敏。**

## 如何运行

### 安装

```bash
git clone https://github.com/Lirunyi-123/legal-document-desensitizer
cd legal-document-desensitizer
pip3 install -r requirements.txt   # jieba（必装）+ docx/pdf/加密（可选）
cd format-converter && npm install && cd ..   # 格式转换核心（可选，需 node >= 22.13）
```

### 常用命令

```bash
# 格式预处理（format-converter，可选）：docx/pdf/html/csv/图片 → txt/md/json
node format-converter/cli.js 判决书.pdf txt -o 判决书.txt
node format-converter/cli.js 合同.docx txt -o 合同.txt
node format-converter/cli.js 裁判文书.html md
node format-converter/cli.js 当事人.csv json
```
# 扫描敏感信息
python3 desensitize.py scan -f 判决书.docx

# 规则层脱敏（txt/docx/pdf，零模型零联网）
python3 desensitize.py mask -f 判决书.docx

# 两阶段工作流阶段一：脱敏 + 生成审阅清单（供律师把关）
python3 desensitize.py mask -f 判决书.docx --review

# 加密映射表 + 一键还原
python3 desensitize.py mask -f 合同.docx --save-mapping 映射表.enc --encrypt-mapping
python3 desensitize.py restore -f 合同_desensitized.docx -m 映射表.enc -o 还原.docx

# 可选：规则层 + 本地/云端 LLM 完整脱敏（非默认依赖）
python3 desensitize.py full -f 判决书.docx --llm-model qwen2.5

# v3.0：PDF 真·涂黑脱敏（保留版式，清元数据/批注/表单/书签/附件，residual 零残留）
python3 desensitize.py mask -f 判决书.pdf --pdf-redact -o 判决书_redacted.pdf

# v3.0：合成语料管线（LLM 写模板 + 代码注入合法校验值，自动填期望）
python3 synthetic/generate_synthetic_pii.py -n 300     # → 测试/合成语料.jsonl

# 红队评测（v3.0：per-tag P/R/F1 + support，合成语料可作第二基线）/ 一键自检
python3 evaluate.py
python3 evaluate.py -c 测试/合成语料.jsonl
python3 selfcheck.py
```

### 一键自检（推荐给所有使用/宣传对象）

```bash
python3 selfcheck.py
```

输出全部 PASS 即证明拷贝与官方版本行为一致。

## 注意事项（安全边界）

### 安全等级，请对号入座

| 操作 | 替换了什么 | 还剩什么 | 能否上传云端 AI |
|------|-----------|---------|----------------|
| 规则层 mask（阶段一） | 关键信息（身份证/手机/银行卡/案号等）+ 人名/公司名/地址/金额 | 法院名称、案情细节、公司简称、OCR 变体 | ⚠️ 须先经审阅清单确认 |
| 规则层 + Agent 语义层（默认，无需外部 API） | 上述全部 + 语义层低优先级信息 | 无 | ✅ 可以 |
| 规则层 + 本地 LLM（full） | 上述全部 + 案情细节/公司名 | 无 | ✅ 可以（模型在本地） |
| 规则层 + 云端 API（full） | 上述全部 | 无 | ✅ 但 LLM 那一步数据会到服务商 |

### 必须知道的三件事

1. **规则层结果必须先过审阅清单**：`mask --review` 的关键信息校验要 ✅，
   剩余低优先级项逐条确认后再用于分享/上传
2. **映射表是敏感文件**：含全部原始值，务必加密保存（`--encrypt-mapping`），
   切勿上传网络或交给无关人员
3. **云端 LLM 方案数据出境**：人名、地址、案情会发送给 API 服务商；
   涉密材料请用本地 Ollama 或纯规则层 + 人工复核

## 已知不足与边界（不回避）

1. **语义层需要"配置了本技能的 AI"来执行**：在无 AI 的环境中批量处理时，
   才需要本地 Ollama 或云端 API 作为替代；规则层不承诺覆盖
   法院名称、案情敏感细节、裸公司简称、OCR 变体写法
2. **裸人名是启发式**：罕见姓氏、单次出现且带数字的三字名（如"张三丰"
   只出现一次时截为"张三"）、网络昵称（"李哥"）存在漏判或过度脱敏
3. **jieba 是必装依赖**：缺失时裸人名发现自动关闭
4. **格式保真有限**：docx 保留段落结构；PDF 输出为纯文本（格式复杂还原难）
5. **format-converter 只做文本层提取**：docx→txt/md 依赖 mammoth（不解析复杂
   宏/嵌入对象），pdf→txt 仅限带文本层的电子版文书；扫描件 PDF 需先走 OCR
   通道（macOS Vision 内置 / Windows/Linux 外部 OCR），图片型材料转 PDF 后
   脱敏效果取决于 OCR 识别率
5. **仅面向中文法律文书**：英文/其他语种的实体规则未覆盖
6. **`full` 命令依赖模型执行力**：不同模型效果有差异，须用
   `evaluate.py --llm-api ...` 实测后再决定是否采用
